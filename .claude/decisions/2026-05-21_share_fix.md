# Share Project Modal — make sharing actually work

**Status:** locked
**Date:** 2026-05-21

## Problem

Investors reported the Share Project modal in Explore was broken:

1. Tapping "Share on WhatsApp" did nothing — no app, no tab.
2. There was no real public link — the previous Copy Link button
   produced a `growize.app/explore/<id>` URL but that route was
   gated behind sign-in, so anyone clicking the shared link bounced
   to `/auth` and never saw the project.
3. The modal still felt unrefined after the last redesign.

## Why the share button was failing

The previous implementation in `lib/features/explore/widgets/share_project_modal.dart`
wired both share buttons to a `_stub()` helper that only surfaced a
"coming soon" SnackBar:

```dart
ElevatedButton.icon(
  onPressed: () => _stub(context, 'WhatsApp'),
  ...
)
```

The comment on `_stub` was explicit:

> `share_plus` isn't on pubspec — surface the intent until v1.1 ships.

So the user feedback was correct: the modal looked functional but
the WhatsApp / native share paths were placeholders. The Copy Link
path did write to the clipboard, but the URL it produced led to a
route that required auth.

## Changes

### 1. `pubspec.yaml`
Added `share_plus: ^10.1.4` as a real dependency so we can call the
OS native share sheet.

### 2. `lib/core/constants/app_links.dart` *(new)*
Single source of truth for the public share origin:

```dart
const String kPublicShareDomain = 'https://growize.app';
String publicProjectShareUrl(String id) =>
    '$kPublicShareDomain/explore/$id';
```

When the production web hostname moves (e.g. to
`https://invest.agresearchlabs.com`) only this constant changes.

### 3. `lib/features/explore/widgets/share_project_modal.dart`
- Removed the `_stub()` SnackBar handlers.
- **Share on WhatsApp** → opens `https://wa.me/?text=<encoded message>`
  via `launchUrl(uri, mode: LaunchMode.externalApplication)`. We
  deliberately use the universal `wa.me` HTTPS link instead of the
  `whatsapp://` scheme — the latter silently no-ops on Chrome / web
  builds. `externalApplication` mode ensures Chrome opens a new tab
  and Android hands off to the WhatsApp app.
- **Copy share link** → writes `kPublicShareDomain/explore/<id>` to
  the clipboard and confirms with a primary-coloured SnackBar +
  check icon ("Link copied to clipboard").
- **More sharing options** → calls `Share.share(text)` from
  `share_plus`, which presents the native OS share sheet on Android
  / iOS (WhatsApp, Telegram, Email, Messages, Copy…). On web there
  is no system share sheet, so we fall back to copy-to-clipboard
  with a "Message copied — paste it anywhere" snackbar.
- Composed message format now matches the brief:

  ```
  I came across this amazing project — {projectName} — on Growize
  and thought you might find it interesting.

  {caption if present}

  {publicShareUrl}

  — {sharerName}
  ```

  The caption field above the buttons starts empty with a
  placeholder ("Add a personal note (optional)") and gets prepended
  to the auto-generated body when the investor sends.
- UX polish:
  - Header simplified to a single "Share this project" title +
    close icon. The redundant mode-chip ("MARKETPLACE MODE") and
    duplicate project name are gone — the project name is already
    the headline of the preview card immediately below.
  - Three full-width pill buttons stacked with 12-px gaps:
    WhatsApp (brand green `#25D366`), Copy Link (outlined primary),
    More Options (outlined muted).
  - Caption field has a hint and no shouty all-caps label.
  - 12-px corner radii throughout; modal background `ArlColors.cream`.

### 4. `lib/core/navigation/router.dart`
Added `_isPublicLocation()` so paths under `/explore/<projectId>`
are reachable without sign-in. We chose **Option A** from the brief
(allow the existing Explore detail route to render in anon mode)
rather than spinning up a separate `/p/<shortId>` micro-route —
that's a smaller diff and the marketplace project rows are already
RLS-readable by `anon`. The Explore detail screen's consultation
form continues to require auth at submission time; an anon viewer
hitting "Request consultation" will be bounced to `/auth` by the
existing flow.

Signed-in users still get bounced *off* `/auth`, `/login`, `/setup`,
`/legal/*` — that subset is now tracked separately as `isAuthRoute`
so we don't bounce a signed-in investor away from a shared
`/explore/<id>` link.

## What now works

|                          | Web (Chrome)                                                                 | Android                                                          |
|--------------------------|------------------------------------------------------------------------------|------------------------------------------------------------------|
| Share on WhatsApp        | Opens `wa.me` in a new tab → user picks contact in WhatsApp Web              | Hands off to the WhatsApp app with the message pre-filled        |
| Copy share link          | Copies `https://growize.app/explore/<id>` to clipboard + snackbar            | Same                                                             |
| More sharing options     | Falls back to copy-message-to-clipboard (no OS share sheet on web)           | Opens Android share sheet (WhatsApp / Telegram / Mail / etc.)    |
| Anon viewer of the link  | Sees marketplace project detail; "Request consultation" prompts sign-in      | Same                                                             |

## Public link format

`https://growize.app/explore/<projectId>`

Built via `publicProjectShareUrl(projectId)` in
`lib/core/constants/app_links.dart`. Domain swap is one constant
change.
